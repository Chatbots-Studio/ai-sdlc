# ai-sdlc

Cursor-first пакет для **самовідновлюваного AI-driven SDLC**.

Цей репозиторій лише для читання. Підключіть його в Cursor — і агенти, скіли,
правила та команди стають доступними у ваших проєктах. **Кроку встановлення
немає** — нічого не копіюється у ваш репозиторій.

🇬🇧 [Read in English](README.md)

## Що таке ai-sdlc?

`ai-sdlc` додає повторюваний AI-процес інженерії поверх будь-якого репозиторію.

Ідея: сам репозиторій є джерелом істини. Агенти Cursor перевіряють зміни проти
специфікацій, що зберігаються в репозиторії, нарощують ці специфікації з часом,
пропонують тести для критичної поведінки, запускають потрібні тести та
ескалюють, коли впевненість низька, замість того щоб вгадувати.

## Як цим користуватися

1. У Cursor підключіть цей репозиторій (`Chatbots-Studio/ai-sdlc`).
2. Відкрийте свій цільовий проєкт.
3. Один раз запустіть команду bootstrap, щоб засіяти специфікації (див. нижче).
4. Викликайте агентів (`@diff-analyzer`, `@spec-matcher`, `@test-runner`, …) на
   своїх змінах.

Налаштування для команди / Background Agents описано в
[docs/cursor-cloud-team-setup.md](docs/cursor-cloud-team-setup.md).

## Bootstrap

Запустіть команду bootstrap у новому репозиторії:

```txt
bootstrap-ai-sdlc
```

Вона просить Cursor просканувати репозиторій, побудувати мапу модулів, обрати
1-3 критичні модулі-засіви, створити початкові специфікації та оновити
`specs/_index.md` і `specs/_coverage.md` — не торкаючись бізнес-коду. Вона
пропонує e2e-тести лише тоді, коли тестовий фреймворк і спосіб запуску зрозумілі;
інакше записує TODO-нотатки щодо покриття.

## Агенти

Розташовані в `.cursor/agents/`. Викликаються через `@name`.

| Агент | Коли використовувати | Що робить |
| --- | --- | --- |
| `@diff-analyzer` | На початку будь-якого рев'ю | Розбирає diff, класифікує змінені файли, зіставляє їх із відповідними специфікаціями та модулями. Лише читання. |
| `@spec-matcher` | Після diff-analyzer | Перевіряє diff проти відомих інваріантів і критичних шляхів специфікацій, позначає порушення. Лише читання. |
| `@test-runner` | Коли потрібні тести | Обирає найвужчий корисний набір тестів і запускає їх лише коли команда й середовище зрозумілі. Вимагає screenshot/video артефакти для UI/browser/e2e тестів або пояснює, чому це неможливо. |
| `@self-healer` | Коли тести падають | Обережно діагностує збої та застосовує лише виправлення з високою впевненістю. Максимум 3 спроби, ескалація нижче 80% впевненості, ніколи не виправляє ризиковану бізнес-логіку автоматично. |
| `@knowledge-grower` | Після мержу PR | Основний агент. Вирішує, чи потрібна зміні нова специфікація, оновлення специфікації, нове регресійне покриття чи лише оновлення метаданих покриття — саме це робить репозиторій розумнішим із часом. |

## Скіли

Розташовані в `.cursor/skills/`. Використовуються агентами (або напряму) для
вузьких підзадач.

| Скіл | Використовувати коли |
| --- | --- |
| `spec-generator` | Потрібна нова специфікація чи її оновлення для поведінки, що має залишатися стабільною. |
| `e2e-generator` | Критичний шлях не має покриття тестами, або багфікс має стати регресійним тестом. |
| `criticality-classifier` | Треба вирішити, чи потребує зміна специфікацій, сильніших тестів, людського рев'ю або ескалації. |
| `kb-indexer` | Змінилися специфікації, тести, власники, критичність чи метадані покриття і треба оновити `specs/_index.md` / `specs/_coverage.md`. |

## Правила

Завжди активні / обмежені за областю настанови в `.cursor/rules/`:

- `ai-sdlc-core.mdc` — базова поведінка; репозиторій є джерелом істини (завжди активне).
- `specs-conventions.mdc` — як пишуться специфікації (діє в межах `specs/`).
- `test-conventions.mdc` — як пишуться згенеровані тести (діє для тестових файлів).

## Ключові концепції

- **Репозиторій як джерело істини** — код, специфікації, тести й рішення живуть
  у репозиторії, щоб агент міг міркувати про поведінку.
- **Живі специфікації** — `specs/` це база знань, а не статична документація:
  критичні модулі, інваріанти, критичні шляхи, власники, пов'язані тести,
  відкриті питання.
- **Рев'ю з урахуванням специфікацій** — `@diff-analyzer` → `@spec-matcher` → `@test-runner`.
- **Самовідновлювані тести** — `@self-healer` пропонує лише обережні виправлення.
- **Ескалація на основі впевненості** — агенти діють за наявності сильних доказів
  і ескалюють із контекстом в інших випадках. Пороги див. у [AGENTS.md](AGENTS.md).

## Структура репозиторію

```txt
AGENTS.md                 Інструкції роботи агентів і правила впевненості
.cursor/
  agents/                 diff-analyzer, spec-matcher, test-runner, self-healer, knowledge-grower
  skills/                 spec-generator, e2e-generator, criticality-classifier, kb-indexer
  rules/                  ai-sdlc-core, specs-conventions, test-conventions
  commands/               bootstrap-ai-sdlc
specs/                    каркас бази знань _index.md, _coverage.md
docs/                     документація з налаштування та автоматизації
```
