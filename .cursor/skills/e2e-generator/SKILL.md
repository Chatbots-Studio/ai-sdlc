# E2E Generator

## Use When

`@knowledge-grower` finds a critical path without test coverage, or a bugfix
should become a regression test.

## Inputs

- Relevant spec and critical paths.
- Existing test directory structure and helper patterns.
- Application setup, fixtures, factories, and cleanup conventions.
- Test command from package scripts or project docs.

## Process

1. Read the spec and extract invariants plus critical paths.
2. Inspect existing tests before writing new ones.
3. Choose the narrowest test level that proves the behavior end to end for the
   project.
4. Follow existing naming, fixtures, setup, and teardown.
5. Add a `spec-ref` comment when the test framework allows comments.
6. Prefer realistic behavior over broad mocks for critical paths.
7. Run or document the exact test command.

## Test Header Template

```js
// spec-ref: specs/example-module/spec.md
// critical-path: main-success-path
// source: generated by ai-sdlc knowledge-grower
```

## Rules

- Cover at least the main success path for critical behavior.
- Include at least one failure or regression path when evidence exists.
- Do not weaken existing tests.
- Do not invent missing product requirements.
- Escalate when setup requirements are unclear.
